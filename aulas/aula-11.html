T1 · tutorial

Mão na massa: a análise de mercado em 5 passos

É a atividade da aula, passo a passo. Para não ficar no abstrato, cada passo mostra um exemplo pronto com o Lanche Já, a lanchonete do campus com pedido antecipado pelo celular (o caso da aula 4). O exemplo é fictício: copie o modelo e troque pelo negócio do grupo.

Antes de começar

Uma página no Loop para a análise

Faça assim:
  1. No workspace do grupo no Loop, crie uma página chamada Análise de mercado.
  2. Crie nela cinco títulos, um para cada passo: Clientes, Pesquisa, Concorrentes, 4 Ps e Dados do sistema.
  3. Dividam o trabalho: cada integrante fica responsável por um passo, mas todo mundo revisa tudo no fim.
Passo 1 · item 1 da atividade

Quem é o cliente: a ficha do cliente

"Todo mundo" não é cliente. O perfil do cliente é a descrição de quem sente a dor que o negócio resolve, com detalhes: quem é, o que faz, como resolve o problema hoje e quanto pagaria pela solução.

Faça assim:
  1. Copie a ficha abaixo para a página do Loop.
  2. Preencha para o cliente principal do negócio de vocês. Tem dois tipos de cliente (quem compra e quem vende, por exemplo)? Uma ficha para cada.
  3. Na linha "Como resolve hoje", sejam honestos: é daí que saem os concorrentes do passo 3.

Passo 2 · itens 1 e 4 da atividade

Perguntar para quem importa: a pesquisa no Microsoft Forms

A lição do estudo de caso: pesquisa com os amigos engana. A pesquisa vai para quem tem o perfil do passo 1. Cinco perguntas bastam, e a meta é ter pelo menos 15 respostas de clientes de verdade.

Faça assim:
  1. Abra forms.office.com com a conta da faculdade e clique em Novo formulário.
  2. Dê o título (por exemplo, "Pesquisa: lanche no intervalo") e uma frase dizendo para que serve e que é anônima.
  3. Clique em + Adicionar novo e crie as perguntas do modelo abaixo, trocando pelo negócio de vocês.
  4. Clique em Coletar respostas, copie o link e mande para quem tem o perfil do cliente (não para os amigos do grupo).
  5. Na aba Respostas, veja os gráficos. Abra no Excel (Abrir resultados no Excel) para contar e calcular as porcentagens.

Passo 3 · itens 2 e 4 da atividade

Os concorrentes, com a IA e com as fontes conferidas

Concorrente não é só quem faz igual: é tudo o que o cliente usa hoje para resolver o problema (a linha "Como resolve hoje" do passo 1). O Copilot ajuda a achar e organizar, mas dado sem fonte não entra no plano.

Faça assim:
  1. Abra o Copilot do Microsoft 365 e use o pedido modelo abaixo, trocando o negócio e a cidade.
  2. Para cada concorrente da resposta, abra o link da fonte e confira se a informação está lá. Não abriu ou não confirmou? Risque.
  3. Monte a tabela no Loop com pelo menos três concorrentes, incluindo o "jeito de hoje" (a marmita também concorre).
  4. Na última coluna, escrevam como o negócio de vocês vai ser diferente de cada um.

Passo 4 · item 3 da atividade

Os 4 Ps: produto, preço, praça e promoção

Com o cliente, a pesquisa e os concorrentes na mão, as decisões de marketing ficam muito mais fáceis. Cada P responde a uma pergunta, e cada resposta precisa ter um motivo que veio dos passos anteriores.

Faça assim:
  1. Copie a tabela para o Loop e responda cada pergunta para o negócio de vocês.
  2. Na coluna "Por quê", apontem de onde veio a decisão: a ficha do cliente, a pesquisa ou a tabela de concorrentes.

Passo 5 · item 5 da atividade

Do marketing ao banco: atualizar o banco.sql

Os 4 Ps viram dados. O produto e o preço viram a tabela produto; o pedido pelo site vira a tabela pedido. E a LGPD vale aqui também: guardem só os dados do cliente que o sistema usa de verdade.

Faça assim:
  1. Abra o banco.sql da aula 10 no VS Code e acrescente as tabelas que os 4 Ps pediram. O modelo abaixo é o do Lanche Já: copie e adapte.
  2. Ligue o Apache e o MySQL no painel do XAMPP e abra http://localhost/phpmyadmin.
  3. Clique na aba SQL, cole o conteúdo do banco.sql e clique em Executar.
  4. Na lista da esquerda, abra o banco e confira as tabelas. Clique em produto › Visualizar: os produtos de teste estão lá?
  5. Faça o commit: git add ., git commit -m "banco.sql com produto e pedido" e git push.
banco.sql (exemplo: Lanche Já)
1-- apaga e cria de novo: dá para rodar quantas vezes precisar2DROP DATABASE IF EXISTS lanche_ja;3CREATE DATABASE lanche_ja CHARACTER SET utf8mb4;4USE lanche_ja;56-- só o que o sistema usa (LGPD): nome e e-mail para avisar que o pedido ficou pronto7CREATE TABLE cliente (8  id INT AUTO_INCREMENT PRIMARY KEY,9  nome VARCHAR(100) NOT NULL,10  email VARCHAR(150) NOT NULL UNIQUE11);1213-- o P de Produto e o P de Preço14CREATE TABLE produto (15  id INT AUTO_INCREMENT PRIMARY KEY,16  nome VARCHAR(100) NOT NULL,17  preco DECIMAL(10, 2) NOT NULL,18  categoria VARCHAR(50)19);2021-- o P de Praça: o pedido feito pelo site, para retirar no intervalo22CREATE TABLE pedido (23  id INT AUTO_INCREMENT PRIMARY KEY,24  cliente_id INT NOT NULL,25  produto_id INT NOT NULL,26  quantidade INT NOT NULL DEFAULT 1,27  retirada TIME NOT NULL,28  criado_em DATETIME DEFAULT CURRENT_TIMESTAMP,29  FOREIGN KEY (cliente_id) REFERENCES cliente(id),30  FOREIGN KEY (produto_id) REFERENCES produto(id)31);3233-- dados de teste34INSERT INTO produto (nome, preco, categoria) VALUES35  ('Misto quente', 9.00, 'lanche'),36  ('Suco natural', 7.00, 'bebida'),37  ('Combo do intervalo', 16.00, 'combo');3839INSERT INTO cliente (nome, email) VALUES ('Ana Souza', 'ana@email.com');40INSERT INTO pedido (cliente_id, produto_id, retirada) VALUES (1, 3, '20:40');

Deu erro no phpMyAdmin? Leia a mensagem: ela diz a linha. Os erros mais comuns são vírgula faltando no fim de uma coluna, vírgula sobrando depois da última coluna e chave estrangeira apontando para uma tabela que ainda não foi criada (a ordem das tabelas importa).

Agora é com você:
  1. Na aba SQL do phpMyAdmin, rode SELECT nome, preco FROM produto ORDER BY preco; e confira os preços.
  2. Desafio: escreva o SELECT com JOIN que mostra o nome do cliente e o nome do produto de cada pedido.

Terminou? Exporte a página do Loop em PDF (ou copie o link) e entregue a análise de mercado no Moodle (item 6 da atividade).

EC1 · estudo de caso

Pesquisa de mercado com cinco amigos

O grupo fictício Eco Ponto perguntou a cinco amigos se usariam um app de pontos de reciclagem. Todos disseram que sim. No lançamento, quase ninguém baixou.

Depois descobriram que o público de verdade (quem recicla toda semana) já usava o grupo do condomínio no WhatsApp.

Para discutir em grupo

  1. Por que a pesquisa com amigos enganou o grupo?
  2. Quem deveria ter sido entrevistado?
  3. Que dados do cliente o banco de vocês precisa guardar, e quais são dados pessoais que a LGPD protege?
